# 프로토타입 002 — 3D 탄종 조합 테스트

밀리터리 슈팅 핵앤슬래시의 핵심 루프를 검증하는 최소 프로토타입.
**기본공격으로 취약 스택을 쌓고 → 스킬(탄종)로 터뜨린다.** 같은 탄종이 든 총에 따라 다르게 나간다.

## 실행 방법

```bash
cd prototype-002-3d-ammo
npm install      # 처음 한 번만
npm run dev
```
터미널에 뜨는 주소(기본 `http://localhost:5173`)를 브라우저로 연다.
여기서 뜨는 `localhost` 는 인터넷 서버가 아니라 **내 컴퓨터 안에서만 도는 로컬 실행**이다.

빌드 확인은 `npm run build`, 정적 미리보기는 `npm run preview`.

## 조작

| 입력 | 동작 |
|---|---|
| WASD | 이동 (화면 위 = -Z) |
| 마우스 | 조준 (지면 레이캐스트) |
| 좌클릭(홀드) | 기본공격 연사 |
| Q | 소이탄 |
| E | 철갑탄 |
| 1 / 2 | 산탄총 / 저격총 교체 |
| Space | 대시(무적) |
| R | 재장전 |

**핵심 감상 포인트:** `1`↔`2`로 총을 바꾸면 좌하단 Q/E 스킬 설명이 같이 바뀐다.
총 2종 × 탄종 2종 = 4가지 패턴이 이 한 줄로 드러나는 게 설계의 뼈대다.

## config.js — 가장 먼저 만져볼 값 3개

모든 튜닝 값은 `src/config.js` 한 곳에 있다. 손맛을 잡으려면 여기부터 본다.

1. **`guns.shotgun.fireInterval` (현재 0.6s)**
   기본공격의 리듬 그 자체. 이 값이 "판 까는 시간"의 템포를 정한다. 너무 길면
   스택 쌓기가 지루하고, 너무 짧으면 스킬 없이 기본공격만으로 다 녹아서 취약 스택이
   무의미해진다. **검증 항목 1**(기본공격→스킬 리듬)을 판단할 때 첫 번째로 건드릴 값.

2. **`vuln.dmgPerStack` (현재 0.25 = 스택당 +25%)**
   스택을 터뜨리는 순간이 얼마나 짜릿한지를 직접 정한다. 이 값을 키우면 "참았다
   터뜨린다"의 보상이 커지고, 낮추면 기본공격 난사가 더 이득이 된다. 스택 5개 만점에서
   최종 배율 = 1 + 5×이 값. **검증 항목 1의 재미가 여기서 갈린다.**

3. **`camera.offset` / `camera.fov` (현재 (0,26,16), FOV 45)**
   **검증 항목 3**(위에서 봤을 때 스킬 형태 구분)이 이 각도에 달려 있다. y를 키우면
   더 수직에 가까워져 부채꼴/직선이 또렷해지지만 원근감(입체감)이 줄고, z를 키우면
   비스듬해져 멋있지만 형태가 뭉개진다. 부채꼴과 직선이 헷갈리면 제일 먼저 이 값을 만진다.

(그 외 `ammo.*.rechargeTime`으로 스킬 빈도, `firePatch.life/dps`로 장판 지속·화력,
`shake.*`로 타격감 강도를 조절한다.)

## 파일 구조

```
src/
  main.js            진입점, 게임 루프, world 컨텍스트
  config.js          ★ 모든 튜닝 값
  core/{input,camera,arena}.js
  entities/{player,enemy,bullet}.js
  systems/
    weapons.js       GUNS = 기본공격 (WeaponController)
    ammo.js          AMMO[탄종][총] = 스킬 분기 (설계 핵심)
    damage.js        피해 적용 + 취약 스택 처리
    waves.js         스폰
    vfx.js           파티클/화염장판/데미지숫자/총구섬광/빔/잔상
  ui/hud.js          DOM 오버레이
```

탄종→총 분기는 명세 그대로 `AMMO[ammoKey][gunKey](world, origin, dir)` 디스패치 테이블로 구현했다.

## 만들면서 "이 설계 이상한데" 싶었던 지점

- **소이탄은 발사체가 아니라 즉발 판정으로 만들었다.** 부채꼴/직선 화염을 "날아가는
  총알"로 처리하면 지면 형태가 프레임마다 달라져 **검증 항목 3**이 흔들린다. 그래서
  소이탄은 시전 즉시 범위/라인 판정 + 지면 장판 생성으로 갔다(철갑탄만 진짜 발사체).
  명세의 "발사"라는 표현과 구현이 살짝 다른 지점이라 짚어 둔다.

- **취약 스택과 화상 DoT가 서로 안 맞물린다.** 스킬은 스택을 "즉발 피해"에만 적용하는데,
  소이탄의 진짜 화력은 지속되는 화상/장판이다. 즉 소이탄으로 스택을 터뜨려도 배율은
  즉발 20~40 피해에만 붙고, 정작 큰 딜인 DoT엔 안 붙는다. 지금은 이게 "스택은 순간
  화력, 소이탄은 지속 화력"이라는 역할 분리로 읽히지만, 플레이해 보고 심심하면 화상
  총량에도 스택 배율을 태우는 걸 고려해야 한다. (`damage.js`의 `applyDamage`가 손댈 곳.)

- **철갑탄 저격총이 스택 구조를 무의미하게 만들 위험.** 단발 150 + 무한 관통 + 스택
  배율이면 스택 5개 터뜨릴 때 375다. 이 조합만 반복하는 게 최적해가 되면 "기본공격으로
  판 깔고 스킬로 터뜨린다"는 리듬이 아니라 "저격 원콤"이 되어 버린다. 밸런스가 아니라
  **검증 항목 1의 성립 여부**에 직결되는 부분이라 플레이 중 눈여겨봐야 한다.

- **접촉 피해가 꽤 아프다.** 100마리가 겹쳐 붙으면 `hurtInvuln`(0.5s)이 있어도 순삭될
  수 있다. 대시 무적으로 빠져나가는 게 의도지만, 웨이브 후반 난이도 곡선은 아직 안
  잡혀 있다(스코프상 밸런싱은 뒤로 미룸).
